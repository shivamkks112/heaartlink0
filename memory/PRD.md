# HeartLink - Product Requirements Document

## Architecture
- **Frontend**: React + Capacitor (Android WebView, CapacitorHttp enabled)
- **Backend**: FastAPI (Python) + MongoDB
- **Push**: Firebase Cloud Messaging (FCM) only — no OneSignal
- **Email**: Resend + Microsoft 365 SMTP fallback
- **LLM**: Gemini 2.5 Flash via emergentintegrations
- **Ads**: Google AdMob (Capacitor native)

## Notification System — Forensic Audit & Fix (July 25, 2026)

### Root Cause:
`pushNotifications.js` had a **RACE CONDITION**: `PushNotifications.register()` was called BEFORE the `'registration'` event listener was added. The FCM token was generated by Firebase but the callback to capture it fired before any listener existed. Result: **zero real users** had FCM tokens in the database. Every notification send returned `{error: "no_token"}`.

### Evidence:
- All 17 real users had `fcm_token: null` in MongoDB
- `POST /api/admin/push/send-to-user/{id}` returned `{error: "no_token"}`
- Firebase Console test sends worked (proving device registration was fine)
- The disconnect was purely: device has token, backend doesn't know it

### Fix:
1. **pushNotifications.js** — Moved ALL 4 `addListener()` calls BEFORE `PushNotifications.register()`. Added `removeAllListeners()` to prevent duplicates. Added 3-attempt retry with 2s/4s backoff for `registerTokenWithBackend`. Added localStorage diagnostics.
2. **server.py** — Added `GET /api/fcm/diagnostics/{user_id}` endpoint. Updated `register-token` to store `fcm_token_updated_at`. Fixed `/admin/push/send` double-send quirk.
3. Cleaned fake `TEST_*` tokens from database.

### Why this fix is permanent:
- Listeners are guaranteed to be set before register() fires
- Retry logic handles transient network failures at app boot
- Diagnostics endpoint enables live debugging
- Stale token auto-cleanup in fcm_service.py handles expired tokens

## Key Files
- `/app/backend/fcm_service.py` — FCM notification service (all events)
- `/app/backend/server.py` — Main server (7472 lines)
- `/app/frontend/src/services/pushNotifications.js` — FCM client (fixed race condition)
- `/app/frontend/capacitor.config.json` — CapacitorHttp + Android config

## API Endpoints (Push)
- `POST /api/fcm/register-token` — Register device FCM token
- `GET /api/fcm/diagnostics/{user_id}` — Notification diagnostics
- `POST /api/admin/push/send` — Admin broadcast
- `POST /api/admin/push/test` — Test notification
- `GET /api/admin/push/status` — FCM status
